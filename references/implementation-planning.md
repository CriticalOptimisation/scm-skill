- **Objective**: Turn the assessment into a practical plan.
- **Activities**:
  - Work from the main worktree on `main`, read-only: no branch is created and no git-tracked file changes in this task. The branch is created at the start of Task 4, once the plan is approved.
  - Break down the work into specific tasks, identify files/components to change, and roughly describe their interactions.
  - Plan the testing strategy (unit/integration/manual) without repeating the high-level blocker list from Task 2 (since we assume no major blockers remain after Task 2 approval).
  - Update the issue with the plan and note any tooling or skill dependencies.
  - Review reviewer comments and consider their implications for the plan.
- **Validation**: The plan is comprehensive and recorded in the issue using markdown, the files to change are scoped accordingly, and the human reviewer has approved the plan.
